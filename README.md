# CS 210 Programming Languages
## Airgead Banking Project

### Summarize the project and what problem it was solving.
For this project, I created an investment calculator for Airgead Banking. The program allows the user to enter an initial investment amount, monthly deposit, annual interest rate, and number of years. It then calculates and displays how the investment grows over time with and without additional monthly deposits. The goal of the project was to create a program that could help users better understand saving, investing, and how compound interest can affect their money over time.

### What did you do particularly well?
I think one of the things I did well was continuing to work through the project even though I had fallen about a week behind in the course. Being behind made completing some of the assignments more difficult, but I was still able to get the Airgead Banking program working and meet the main requirements of the project. I also think I improved at organizing my code by separating the program into different functions and files instead of putting everything inside `main()`.

### Where could you enhance your code? How would these improvements make your code more efficient, secure, and so on?
One area I could improve is input validation. The program could do a better job of handling situations where a user enters something unexpected, such as a negative number or letters where a number is required. Better input validation would make the program more reliable and prevent invalid input from causing problems. As I gain more experience with C++, I would also like to go back through the program and see where I could simplify the code and make it more efficient.

This project gave me more experience working with C++ classes, functions, header files, calculations, formatted output, and debugging. I also learned more about breaking a larger program into smaller pieces instead of trying to solve everything at once. ### How did you make this program maintainable, readable, and adaptable?
I tried to make the program easier to maintain by separating different responsibilities into functions and using descriptive names for variables and methods. I also used comments to explain important parts of the code. Separating the program between `Main.cpp`, `Investment.cpp`, and `Investment.h` keeps the code more organized and makes individual parts easier to change without having to rewrite the entire program. Looking back at the project, I can see how keeping code organized becomes more important as programs become larger.
